## 0. 목표와 성공 기준

**목표**: 신청자 앱·링크 페이지·운영콘솔을 "실제로 운영 중인 서비스"처럼 보이고 동작하게 만든다. 레이아웃·스타일뿐 아니라 **콘텐츠 구성(무엇을 보여주는가)**을 함께 채운다.

**성공 기준**
1. 첫 화면에서 사진·실제 일정·잔여석·후기가 보이고, 알약 라벨·3칸 USP 카드·이모지 썸네일 같은 템플릿 요소가 없다.
2. 모임 상세만 보고 "누구와, 무엇을, 얼마에(무엇이 포함돼서), 언제, 어디서, 취소하면 어떻게 되는지"를 모두 알 수 있다.
3. 상세에서 일정을 고르고 신청을 마칠 때까지 불필요한 단계가 없다(현재 4단계 → 상세 안 일정 선택 + 1단계 정보 입력).
4. 승인 → 참여 확정 → 입금까지 신청자가 **다음에 해야 할 일을 항상 알 수 있다**(입금 계좌·금액·마감 시각 안내).
5. 운영자가 콘솔에서 새 콘텐츠 필드(사진, 추천 대상, 제공사항, 호스트 소개 등)를 직접 입력·수정할 수 있다.
6. 사용자에게 보이는 문구에 개발 메모("테스트 버전", "PG 연동 후…")가 없다.
7. 430px 모바일, 데스크톱, 다크모드 세 환경에서 레이아웃이 깨지지 않는다.

**범위 밖** (이번에 하지 않음): 회원가입·로그인, 찜 저장, PG 결제, 카카오 알림톡 실발송, 지도 API 임베드, 이미지 업로드 기능, 희망 일정 알림 신청 테이블.

### 2.2 타이포그래피

- 본문/UI: **Pretendard Variable** (`cdn.jsdelivr.net/gh/orioncactus/pretendard` dynamic-subset)
- 제목: **Pretendard 800** (`.heading`) — 모임명, 페이지 제목, 큰 숫자. 로고 글자만 `--font-logo`(나눔스퀘어라운드 ExtraBold 수정본, `public/assets/fonts/`). *2026-09-26 이전에는 Noto Serif KR 명조였음*
- 스케일: `12 / 13 / 14 / 15(본문) / 17 / 20 / 24 / 28` px, 본문 행간 1.6, 제목 행간 1.3, 한글 `word-break: keep-all`
- 숫자(가격·시간·잔여석)는 `font-variant-numeric: tabular-nums`

### 2.3 형태·간격

- 간격 단위 4px (토큰 `--sp-4`·`--sp-8`… , 2026-09-24부터 CSS에서 강제). 화면 좌우 여백 **20px**. 상세 섹션 간 **40px + 1px 구분선**, 홈 섹션 간 **36px**
- 라운드: 사진 **8px**, 버튼 **10px**(알약형 금지), 칩 **6px**, 시트 상단 16px. "카드 안의 카드" 금지 — 정보 묶음은 `--bg-sunken` 면 하나로
- 최대 폭: 신청자 앱 **480px 가운데 컬럼**, 데스크톱에서는 좌우 `--bg-sunken` 여백. **폰 목업 프레임 제거**
- 터치 영역 최소 44px

### 2.4 아이콘

이모지를 UI에서 모두 제거하고 **인라인 SVG 아이콘 세트**(Lucide 기반, MIT, 1.75px 선, 20px)를 `common.js` 에 스프라이트로 둔다: `chevron-left/right, share, map-pin, clock, users, calendar, wallet, info, check, x, star, message-circle, phone, menu, sparkle(사용 안 함)`.

### 2.5 브랜드 모티프 — "세 자리"

서비스의 핵심 사실(**최대 3명**)을 장식이 아닌 정보로 반복한다.
- **좌석 점 표시** `●●○` : 채워진 자리 = 확정 인원, 빈 자리 = 남은 자리. 카드·일정 선택·상세 요약 어디서나 같은 컴포넌트. 옆에 `1자리 남음` 텍스트(마지막 1자리는 `--accent`)
- 워드마크: 로고 마크 + `오늘의 취향` 나눔스퀘어라운드 ExtraBold(2026-09-26 변경, 이전 Noto Serif KR). 마크는 **'향'의 ㅎ을 뚜껑 덮인 옹기로 그리고 안을 주홍(오늘의 취향)으로 채운 것**(2026-09-24 교체, 이전 세 점 로고 대체). 원본 `icons/favicon.svg`, 헤더는 같은 도형을 `currentColor`+`--accent` 인라인 SVG로 써서 다크 모드에서 자동 반전. 16px에서 뭉치지 않도록 꼭지–가로획–잔 간격 3.5 이상(64 그리드), 획 6.2 유지
- 카피 톤: "작은 테이블", "세 사람" 같은 표현을 **히어로와 소개 1곳에서만** 사용(반복 금지)

### 2.6 문구 원칙

1. 해요체, 한 문장 한 정보. 형용사("검증된", "특별한") 대신 **숫자·사실**("12회 진행", "재료비 포함", "자정 기준")
2. 같은 주장은 화면당 한 번만. "운영진이 확인한 모임" 문구는 상세 요약 블록 1곳
3. 버튼은 결과를 말한다: `다음` → `이 일정으로 신청하기`, `신청서 제출하기` → `신청 보내기`
4. 개발·테스트 메모는 사용자 화면에 쓰지 않는다(운영콘솔 도움말로 이동)
5. 오류는 원인 + 해결 방법: "이미 이 일정에 같은 번호로 신청했어요. 신청 현황은 카카오톡 채널로 문의해 주세요."

## 3. 정보 구조와 라우팅

신청자 앱의 라우팅을 **해시 라우터**로 바꾼다. 현재는 메모리 스택이라 브라우저 뒤로가기가 사이트를 벗어나고 상세 링크를 공유할 수 없다.

| 경로 | 화면 | 비고 |
|---|---|---|
| `#/` | 홈 | |
| `#/g/:id` | 모임 상세 (일정 선택 포함) | 공유 가능 |
| `#/g/:id/apply?s=:scheduleId` | 신청 정보 입력 | 일정 미선택 시 상세로 돌려보냄 |
| `#/done` | 신청 완료 | 새로고침 시 홈으로 |
| `#/find` | 시간대로 찾기 (기존 매트릭스 → 추천) | 홈 진입점에서만 |
| `#/guide` | 이용 안내 (신청 → 승인 → 참여 확정 → 입금 → 당일 + 환불 공통 원칙) | |
| `#/policy/privacy`, `#/policy/terms` | 약관 | |

`/participation/:token`, `/review/:token` 은 기존처럼 서버가 별도 HTML로 서빙.

## 4. 화면별 설계

### 4.1 홈 `#/`

위에서 아래로:

1. **헤더** (56px, 스크롤 시 하단 선): 좌 `워드마크` · `대구` 지역 라벨 / 우 `이용 안내` 텍스트 링크. 운영콘솔 링크는 제거(푸터로)
2. **브랜드 배너** (사진 1장, 16:10, 8px 라운드): 사진 위 좌하단에 흰 글자 2줄 "퇴근 후 두 시간, / 처음 만난 세 사람과 만드는 취향" + 작은 링크 `오늘의 취향은 어떻게 운영되나요 >` (→ `#/guide`). 캐러셀 없음 (모임 수가 적어 1장이 정직함)
3. **빠른 필터 칩 행** (가로 스크롤): `전체` `이번 주말` `평일 저녁` `만들기` `배우기` `마감 임박` — 실제 일정 데이터로 필터링(문토 앵글 아이콘의 역할을 텍스트 칩으로 가볍게)
4. **시간대로 찾기 진입 카드** (`--bg-sunken` 면 1개): "언제 시간 되세요?" / "요일과 시간대를 고르면 맞는 모임을 골라드려요" / `시간대 고르기 >` → `#/find`
5. **섹션 "이번 주 열리는 모임"** + 부제 "7일 안에 열리는 일정이에요" — 가로 스크롤 **세로 카드**(4.5 참고). 7일 내 일정이 없으면 섹션 숨김
6. **섹션 "모든 모임"** + 부제 "{N}개 모임 · {M}개 일정 모집 중" — 필터 칩 결과를 **2열 그리드**(모바일)로
7. **섹션 "다녀온 분들의 후기"** + 부제 "참여 후 직접 남긴 평가예요" — 후기 카드 가로 스크롤(★점수, 원문 3줄 말줄임, `박** · 향수 만들기 · 9월 참여`). 공개 후기 0건이면 숨김
8. **"처음이라면" 안내 블록**: 5단계를 한 줄씩(숫자 + 동사 + 한 줄 설명)으로. 특히 "승인되면 카카오톡으로 참여 확인 링크를 보내드려요 → 참여를 확정하면 **10시간 안에 입금**" 을 명확히
9. **FAQ** 4개 (아코디언) + `이용 안내 전체 보기`
10. **푸터**: 고객센터(카카오톡 채널 링크 + 운영시간) · 이용약관 · 개인정보처리방침 · 사업자 정보(상호, 대표, 사업자등록번호, 통신판매업, 주소 — `site-config.js`) · `운영자 로그인` 작은 링크

**삭제**: 알약 eyebrow, 3칸 신뢰 카드, 초록 인증 박스, 🎲 랜덤 스트립(랜덤 추천은 `#/find` 결과 화면 안으로만 유지).

### 4.2 모임 상세 `#/g/:id`

상단은 문토(결정 정보를 빨리), 본문은 남의집(읽는 콘텐츠).

1. **커버 갤러리**: 4:3 전폭, 가로 스와이프(`scroll-snap`), 우하단 `1/4` 카운터. 좌상단 뒤로(원형 반투명 X — 흰 원 + 아이콘), 우상단 공유(Web Share API, 미지원 시 링크 복사 + 토스트)
2. **제목 블록**
   - `만들기 · 향수` (13px, `--ink-3`)
   - **모임명** Noto Serif KR 24px
   - 한 줄 소개(tagline) 15px `--ink-2`
   - 신뢰 줄: `★ 4.9 (후기 12)` · `12회 진행` · `누적 31명 참여` — 값이 0이면 해당 항목 숨김, 전부 0이면 `새로 열린 모임` 표시
3. **요약 정보 블록** (`--bg-sunken` 면, 아이콘 + 한 줄씩 — 문토 "안내사항" 방식)
   - [clock 아이콘] `2시간 · 오후/저녁 진행`
   - [users 아이콘] `최대 3명 · 운영자 승인 후 참여 확정` + 좌석 점
   - [wallet 아이콘] `39,000원` + 작은 글씨 `재료비·30ml 공병 포함` (`fee_note`)
   - [map-pin 아이콘] `대구 중구 동성로` + 작은 글씨 `정확한 위치는 참여 확정 후 안내해요`
4. **일정 선택** (앵커 `#일정`) — 남의집 캘린더의 모바일 축약형
   - 제목 "일정 선택" + 부제 "원하는 날짜를 골라주세요"
   - **날짜 칩 가로 스크롤**: `9.28 토` 형태, 일정 있는 날만. 마감된 날은 취소선 + 흐림
   - 선택한 날짜의 **회차 카드**: `오후 2:00 – 4:00` · `동성로 무드랩 2층` · 좌석 점 `●○○ 2자리 남음` · 참가비(회차별 fee가 기본과 다를 때만). 선택 시 `--accent` 테두리 + 체크
   - 일정이 하나도 없으면: "지금은 모집 중인 일정이 없어요" + `다음 일정 소식 받기`(카카오톡 채널 링크)
5. **후기 미리보기** (공개 후기 있을 때): 평균 ★ + 항목별 평균 막대 3개(진행·장소·가격 만족) + 최신 후기 2개 + `후기 전체 보기`(시트)
6. **소개** — Noto Serif 섹션 제목. `intro` 본문(줄바꿈 유지) 사이사이에 갤러리 2~3번째 사진을 끼워 넣음
7. **이런 분께 추천해요** — `for_whom_json` 불릿 (예: "향을 좋아하지만 계열은 잘 모르는 분")
8. **포함 사항** — `includes_json` 체크 아이콘 리스트
9. **진행 순서** — `order_json`. 항목이 `"20분|향의 계열 알아보기"` 형식이면 좌측에 소요시간 표시(하위호환: `|` 없으면 번호만)
10. **준비물** — `prep_json`
11. **호스트** — 사진(원형 56px), `호스트` 라벨, 이름, 경력 한 줄(`host_role`), 소개글(`host_bio`, 3줄 + 더보기)
12. **오시는 길** — 동 단위 장소, `place_note`("동성로 무드랩 2층 · 주차 불가 · 반월당역 도보 5분"), `카카오맵에서 보기` 외부 링크(`https://map.kakao.com/?q=` + 장소명, API 키 불필요), "정확한 위치는 참여 확정 후 안내해요"
13. **환불 규정** — `refund_policy` 를 줄 단위 리스트로 + 공통 문구 "승인 전 취소는 언제나 전액 환불돼요 · 날짜 기준은 자정이에요"
14. **자주 묻는 질문** — `faq_json` 아코디언
15. **다른 모임** — 같은 분야 우선 가로 카드
16. **하단 고정 바**: 좌 `39,000원` + 선택한 일정 요약(`9.28(토) 오후 2:00`) 또는 `일정을 골라주세요` / 우 `신청하기` 버튼. 일정 미선택 상태에서 누르면 일정 선택 영역으로 스크롤 + 흔들림 강조

### 4.3 신청 정보 입력 `#/g/:id/apply?s=`

1단계 화면. 진행 막대 없음(단계가 하나이므로).

- 상단: 선택한 모임 요약 줄(썸네일 48px + 모임명 + 일시 + `변경`)
- 필드: 이름 / 나이(만) / 직업(칩: 대학생·직장인·프리랜서·기타) / MBTI(선택, 칩 그리드 접힘 — "모름"이 기본) / 휴대폰 번호 / **신청 이유**(textarea, placeholder "이 모임에서 기대하는 점이나 관심 계기를 적어주세요. 운영자가 승인할 때 참고해요.", 글자 수 카운터)
- 즉시 검증: 필드 아래 오류 문구(빨간 글자), 제출 버튼 비활성화 대신 **누르면 첫 오류 필드로 스크롤**
- 안내 박스(`--bg-sunken`): "신청 후 과정" 3줄 — 운영자 검토(보통 24시간 안) → 카카오톡으로 참여 확인 링크 → 확정 후 10시간 안 입금
- 동의: [필수] 개인정보 수집·이용 동의(전문 보기 → 시트) / [선택] 새 모임 소식 받기
- 하단 고정 `신청 보내기`
- 나이 제한(19~35)은 서버 정책을 그대로 따르되, 문구를 "만 19~35세만 신청할 수 있어요"로 필드 힌트에 명시

### 4.4 신청 완료 `#/done`

- 체크 아이콘(원형 `--ok-soft`) + 명조 제목 "신청이 접수됐어요"
- **진행 상태 타임라인**(세로): ● 신청 접수(지금) → ○ 운영자 검토 → ○ 참여 확인(카카오톡 링크) → ○ 입금 후 확정. 각 단계 한 줄 설명
- 접수 내역: 접수번호 / 모임 / 일시 / 신청자
- 버튼: `다른 모임 둘러보기`, 보조 링크 `카카오톡 채널로 문의하기`

### 4.5 공용 컴포넌트

- **모임 카드(세로)**: 사진 4:3 8px 라운드 → 사진 좌상단 배지(`N회 진행` `--ok` / `새 모임` / `마감 임박` `--accent`) → `만들기 · 동성로`(13px `--ink-3`) → 모임명(15px 600, 2줄 말줄임, **Pretendard**) → 가장 가까운 일정 `9.28(토) 오후 2시` → 가격 `39,000원` + 좌석 점. 마감된 모임은 사진 흐림 + `모집 마감` 배지
- **좌석 점**: `<span class="seats" data-total="3" data-left="1">` → 점 3개 + 텍스트
- **시트(bottom sheet)**: 약관 전문, 후기 전체, 공유 폴백. 배경 탭/ESC/뒤로가기로 닫힘
- **토스트**: 하단 80px 위, 2.4초
- **로딩**: 스켈레톤(카드 모양 회색 블록). 전체 화면 "불러오는 중" 이모지 제거
- **빈 상태/오류**: 아이콘 + 한 줄 원인 + 행동 버튼(`다시 시도`)

### 4.6 시간대로 찾기 `#/find`

기존 기능 유지 + 한 화면으로 합침: 상단 3×3 매트릭스(평일/토/일 × 오전/오후/저녁) → 아래에 **바로 결과 카드 목록이 갱신**(다음 버튼 없음). 결과 2개 이상이면 `이 중에서 골라주세요` 랜덤 버튼. 선택한 시간대는 `preferred_times` 로 신청까지 전달, 랜덤으로 고른 경우 `selection_method='랜덤'` 유지.

### 4.7 참여 확인 페이지 `/participation/:token`

- 헤더 워드마크, 모임 썸네일 + 모임명 + 일시 + 장소(동)
- 제목 "{이름}님, 신청이 승인됐어요"
- **참여 확정 시 할 일** 박스: 입금 금액 `39,000원` · 입금 계좌 `은행 계좌번호 (예금주)` · 기한 "확정 후 10시간 안 · 기한이 지나면 자동 취소돼요"
- 버튼 `참여할게요`(주) / `이번엔 참여하지 않을게요`(보조, 확인 시트)
- 확정 후: **입금 기한 카운트다운**(`09:59:12 남음`, 1분 단위 갱신) + 계좌 **복사 버튼** + 입금자명 안내("신청자 이름으로 입금해 주세요")
- 만료/사용된 토큰: "이미 처리된 링크예요" + 카카오톡 채널 문의

### 4.8 평가 페이지 `/review/:token`

- 항목 5개를 **별 5개 탭 UI**로(전체 만족도는 크게, 나머지 4개는 한 줄씩)
- 자유 의견 textarea
- **[선택] 후기를 서비스 소개에 공개해도 좋아요** (이름은 박** 으로 가려져요) — 기본 체크 해제
- 문제 신고는 접힌 영역("불편한 일이 있었나요?")으로 분리
- 제출 완료: 감사 문구 + `다른 모임 둘러보기`

### 4.9 운영콘솔 `admin.html`

기능은 유지하고 **같은 토큰으로 시각 체계를 통일** + 새 필드 편집 + 업무 우선순위 표시.

- 레이아웃: 데스크톱 좌측 220px 사이드 내비(신청 관리 / 일정 / 모임체 / 운영자 / 환불 / 평가) + 상단 사용자 메뉴. 800px 이하에서는 상단 탭 + 하단 스크롤
- **신청 관리 상단 "오늘 할 일" 4칸**: 검토 대기 N(접수) · 입금 기한 3시간 이내 N · 오늘 열리는 모임 N · 환불 대기 N — 누르면 해당 필터 적용
- 상태 필터를 셀렉트 → **탭(개수 포함)**으로
- 신청 행 클릭 시 **우측 상세 패널**: 신청 이유(`motivation`), 선호 시간대, 유입 경로, 상태 이력, 액션 버튼
- 모임체 폼을 섹션으로 나눔: 기본 정보 / 사진(커버 URL + 갤러리 URL 여러 줄, 미리보기) / 상세 콘텐츠(소개, 추천 대상, 포함 사항, 진행 순서 `소요시간|내용`, 준비물 — 모두 한 줄에 하나) / 호스트(이름, 경력, 소개, 사진 URL) / 장소·정책(오시는 길 안내, 참가비 포함 내역, 환불 규정, FAQ `질문|답변`)
- 평가: 공개 동의 여부 배지 + **공개 중지** 토글(운영자가 부적절한 후기 숨김)
- 로그인 화면의 "실제 DB 연동 운영콘솔" 같은 개발 문구 제거

## 5. 데이터·API 변경

### 5.1 스키마 추가 (schema.sql + server.js 마이그레이션 루프 + scripts/seed-demo.js 마이그레이션 목록 **세 곳 모두**)

`groups`
| 컬럼 | 타입 | 용도 |
|---|---|---|
| `cover_url` | TEXT '' | 카드·커버 대표 사진 |
| `gallery_json` | TEXT '[]' | 상세 갤러리 추가 사진 URL 배열 |
| `for_whom_json` | TEXT '[]' | 이런 분께 추천해요 |
| `includes_json` | TEXT '[]' | 포함 사항 |
| `fee_note` | TEXT '' | 참가비 포함 내역 한 줄 |
| `host_bio` | TEXT '' | 호스트 소개글 |
| `host_photo_url` | TEXT '' | 호스트 사진 |
| `place_note` | TEXT '' | 오시는 길 안내(층, 주차, 가까운 역) |

`applications`: `motivation TEXT NOT NULL DEFAULT ''`
`reviews`: `publish_ok INTEGER NOT NULL DEFAULT 0`, `hidden INTEGER NOT NULL DEFAULT 0`

기존 `groups.icon` 은 남겨두되 UI에서 쓰지 않는다(사진 없을 때 대체 커버는 분야·태그 타이포그래피).

### 5.2 API

| 엔드포인트 | 변경 |
|---|---|
| `GET /api/public/groups` | 각 그룹에 `stats: {sessions_done, participants, rating_avg, review_count}` (sessions_done = `occurred=1` 일정 수, participants = `참석완료`+`평가완료` 수, 평점은 `satisfaction` 평균, 공개·비숨김 후기 기준) 와 `reviews`(최신 공개 후기 5개: `name_masked, rating, text, date, scores`) 추가. 응답 최상위에 `reviews`(전체 최신 공개 후기 8개, `group_id` 포함) 추가 |
| `POST /api/public/applications` | `motivation` 필수(10~300자) 검증 추가 |
| `GET /api/public/participation/:token` | `fee`, `place`, `payment: {bank, account, holder}`(env `PAYMENT_BANK`, `PAYMENT_ACCOUNT`, `PAYMENT_HOLDER`), `cover_url` 추가 |
| `POST /api/public/participation/:token` | 응답에 `payment` 동일 포함 |
| `GET /api/public/review/:token` | `cover_url`, 일시 추가 |
| `POST /api/public/review/:token` | `publish_ok` 저장 |
| `POST/PATCH /api/admin/groups` | 새 필드 저장 (`for_whom`, `includes`, `gallery` 는 배열로 받음 — 기존 `order/prep/faq` 방식과 동일) |
| `PATCH /api/admin/reviews/:id` (신규) | `hidden` 토글, adminOnly, `audit()` 기록 |

`.env.example` 에 `PAYMENT_BANK`, `PAYMENT_ACCOUNT`, `PAYMENT_HOLDER` 추가. 값이 없으면 참여 페이지에 "입금 계좌는 운영자가 카카오톡으로 안내해요"로 대체.

### 5.3 시드 데이터 보강 (`scripts/seed-demo.js`)

5개 모임체 모두 새 필드를 채운다: 커버·갤러리(03 문서의 에셋 경로), 추천 대상 3~4줄, 포함 사항 2~3줄, `fee_note`, 호스트 소개 3~4문장, `place_note`, 진행 순서에 소요시간, 환불 규정을 줄 단위로. 평가완료 데이터에 `publish_ok=1` 후기 원문을 6~8개 추가해 홈 후기 섹션이 비지 않게 한다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 기존 운영 DB에 새 컬럼이 비어 있어 상세가 빈약해 보임 | 모든 신규 섹션은 값이 없으면 섹션 자체를 숨김. 콘솔 모임체 목록에 "상세 콘텐츠 채움 정도" 표시(예: 5/8) |
| 스톡 사진이 모임 실물과 다름 | 03 문서대로 "분위기 사진"으로만 쓰고, 콘솔에서 실제 사진 URL로 교체 가능. 호스트 사진은 얼굴 대신 작업 공간/손 사진 사용 |
| 신청 이유 필수화로 전환율 하락 | 10자 최소, 예시 문구 제공. 운영 데이터 보고 선택으로 전환 가능(서버 검증 한 줄) |
| 해시 라우팅으로 기존 공유 URL 없음 | 기존에는 공유 가능한 URL이 없었으므로 호환 이슈 없음 |
