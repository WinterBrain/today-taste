## 1. 한 줄 요약

| | 문토 | 남의집 |
|---|---|---|
| 성격 | **탐색형 마켓플레이스**. 모임이 많고, 빨리 훑고 고르게 만든다 | **큐레이션형 매거진**. 모임 하나하나를 이야기로 읽게 만든다 |
| 첫 인상 | 흰 배경, 사진 카드가 가로로 계속 흐름, 빨간 포인트 | 흰/연회색 배경, 명조 제목, 사진 + 긴 호스트 글, 주황 포인트 |
| 신뢰를 만드는 방법 | 후기 수·만족도 %·매너점수·함께하는 멤버 노출 | "N회 진행" 배지·인증 마크·누적 참여 인원·호스트 스토리 |
| 오늘의 취향이 가져올 것 | **홈 탐색 구조, 카드 규격, 상세의 정보 요약 블록, 후기 전면 배치** | **상세 콘텐츠 구성, 명조 에디토리얼 톤, 일정 선택 UI, 단계별 환불 규정** |

### 2.5 기능·정책 (웹 검색 보강)

- 승인제 소셜링은 신청 시 **호스트가 정한 문답**을 작성하고, 호스트가 보고 승인한다. "문답 내용이 부족한 경우 별도 안내 없이 신청 거절될 수 있습니다"를 본문에 명시
- 참여자 **매너점수**가 프로필에 표시되고 승인 판단 근거로 쓰인다
- 흐름: 선택 → 신청 → 승인 → 오픈채팅 입장 → 후기 작성. 모임 4일 전 리마인드 알림, 빈자리 알림 예약
- 가입은 카카오 연동으로 최소화, "귀찮은 절차는 서비스가 담당"

- 플랫폼 심사를 거쳐야 호스트가 될 수 있고, 게스트는 본인인증을 거친다. 호스트가 게스트를 **선별해 초대**하는 구조("7명 초대")
- 한때 서비스를 종료했다가 현재 (주)한페협이 운영 중. 즉 "작은 규모의 승인제 모임"은 신뢰를 콘텐츠로 증명해야 살아남는다는 교훈

## 4. 현재 '오늘의 취향'과의 비교 진단

현재 신청자 앱(`public/index.html`)을 브라우저로 띄워 확인한 결과다.

| 영역 | 현재 | 레퍼런스 기준 문제 |
|---|---|---|
| 전체 인상 | 크림 배경 + 짙은 초록 + 명조 헤드라인 + 알약 라벨 + 3칸 신뢰 카드 + 이모지 | **"AI 랜딩 템플릿"의 전형**. 실제 서비스는 사진이 첫 인상을 만들고, 장식 요소(알약 eyebrow, 3칸 USP 카드, 그라데이션)는 거의 없다 |
| 데스크톱 프레임 | 둥근 폰 목업 테두리 | 실제 모바일 웹은 목업 프레임을 두지 않는다. 가운데 정렬된 흰 컬럼이면 충분 |
| 사진 | **없음**. 이모지(🧴✏️☕🧷📷)를 썸네일로 사용 | 두 서비스 모두 카드·상세·카테고리·호스트까지 **전부 실제 사진** |
| 홈 구조 | 히어로 → 신뢰카드 → 랜덤 → 탭 → 목록 → 참여방법 → FAQ | 섹션마다 "제목 + 부제 + 카드" 리듬 부재. 후기 섹션 없음. 푸터(사업자 정보·고객센터) 없음 |
| 카드 | 가로형 리스트, 이모지 썸네일, 가격 노출 | 사진 중심 세로 카드가 표준. 잔여석·진행 횟수 같은 **판단 정보**가 없음 |
| 상세 콘텐츠 | 소개 1문단, 진행 순서, 준비물, 일정 목록, 운영자 이름, 환불 1문장, FAQ | 빠진 것: 사진 갤러리, **이런 분께 추천**, **제공사항/참가비 구성**, 진행 순서의 소요시간, **호스트 스토리**, **후기**, **오시는 길**(확정 후 안내), 단계별 환불 규정, 진행 실적 |
| 일정 선택 | 상세에서 "신청하기" → 다시 **시간대 매트릭스**부터 시작 | 이미 모임을 골랐는데 시간대 매트릭스를 거치는 건 불필요한 단계. 남의집처럼 **상세 안에서 날짜 → 회차 선택 후 바로 신청**이 자연스럽다 |
| 신청 폼 | 이름·나이·직업·MBTI·전화 | 승인제인데 **"왜 신청하는지"를 묻는 문답이 없음** → 운영자가 판단할 근거가 부족(문토 승인제 문답 참고) |
| 참여 확인 페이지 | 버튼 2개 + 입금 기한 텍스트 | **입금할 계좌·금액이 안내되지 않음**. 실제 운영 불가 수준의 공백 |
| 평가 페이지 | `<select>` 5개 | 별점 UI가 표준. 공개 후기로 쓸 수 있도록 **공개 동의**를 받아야 홈/상세 후기로 재활용 가능 |
| 문구 | "검증된 모임", "운영진이 확인한 모임이에요"가 여러 번 반복 | 같은 주장을 반복하면 오히려 광고처럼 느껴진다. 레퍼런스는 **숫자와 구체적 사실**(N회 진행, 후기 86, 누적 350명, "자정 기준")로 신뢰를 보여준다 |

### 4.1 "AI가 만든 느낌"의 구체적 원인 목록

1. 히어로 위 알약 모양 eyebrow 라벨(`승인제 원데이 모임`) + 대형 명조 2줄 헤드라인 + 부제 + CTA 버튼이라는 **정형 랜딩 공식**
2. **3칸 USP 카드**(`최대 3인` / `검증된 모임체` / `승인제`) — 같은 말을 히어로 배지·신뢰카드·인증박스에서 세 번 반복
3. 이모지를 아이콘·썸네일 대신 사용
4. 크림 배경 + 짙은 초록(파인) + 앰버라는 "무난한 고급" 팔레트, 반투명 그라데이션
5. 모든 요소가 같은 크기의 둥근 박스(카드 안의 카드), 섹션마다 동일한 패딩
6. 실제 데이터(진행 횟수, 후기, 잔여석 추이)가 아닌 **형용사**로 신뢰를 주장
7. 폰 목업 프레임
8. "테스트 버전은…", "PG 연동 후 교체할 수 있어요" 같은 **개발 메모가 사용자 문구에 노출**

## 5. 오늘의 취향에 가져올 원칙 (02 기획서의 근거)

1. **사진이 첫 번째 정보다.** 카드·상세 커버·호스트·공간은 사진으로. 사진이 없을 때의 대체 표현도 이모지가 아닌 타이포그래피 커버로.
2. **신뢰는 숫자와 사실로.** `N회 진행`, `누적 N명 참여`, `★4.9 · 후기 N`, `최대 3명 중 1자리 남음`, "자정 기준", "확정 후 정확한 위치 안내".
3. **홈은 훑게(문토), 상세는 읽게(남의집).** 홈: 섹션 제목 + 부제 + 가로 카드 리듬. 상세: 얇은 선으로 나눈 섹션 + 명조 제목 + 넉넉한 여백.
4. **포인트 컬러는 하나, 나머지는 따뜻한 무채색.** 두 서비스 모두 붉은/주황 계열 1색 + 붉은기 도는 회색 체계.
5. **결정에 필요한 정보는 한 블록에 모은다.** 문토 "안내사항"처럼 분야·방식·인원·참가비(구성)·일시·장소를 아이콘 리스트로.
6. **후기를 본문보다 앞에.** 문토는 커버 바로 아래, 홈에도 후기 섹션.
7. **일정 선택은 상세 안에서 끝낸다.** 날짜 → 회차 → 신청. 가능한 일정이 없으면 "희망 일정 알림 신청" 같은 대안 경로.
8. **실제 서비스의 뼈대를 갖춘다.** 푸터 사업자 정보, 고객센터 채널/운영시간, 약관·개인정보처리방침, 공유 미리보기(OG).
